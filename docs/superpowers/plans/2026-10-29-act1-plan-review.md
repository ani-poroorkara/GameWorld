# Act 1 plan review

Read-only review of the design, plan, source note and existing runtime seams. No baseline tests rerun. Findings describe planning defects and implementation risks, not observed failures in new code.

## Findings to resolve

1. **High — parked puzzle rules become implementation instructions.** `docs/Act 1.md`, “Puzzle design — parked for a later session,” explicitly defers rules, solutions, rewards and unlimited retries. The design's proposal table is appropriately labelled new, but its instruction to keep proposals outside implementation only “until their task begins” and plan Task 11's instruction to implement them remove that deferral automatically. Keep the proposals, but make revisiting the parked decisions an explicit dependency before Task 11 implementation. Tests cannot serve as approval of a previously deferred rule.

2. **High — publication/combat tasks lack a decision dependency.** Tasks 4–5 require approved playable definitions, yet `content/act1.json` has null attack powers and use limits; `docs/Act 1.md` also leaves Staff/Throw interaction unresolved. Task 8 correctly acknowledges that drop probabilities block feature completion, but the equivalent dependency is absent for combat publication. Add a decision checklist before publishing attack cards, food/dice interaction, Pet Distraction/dice interaction and Staff/Throw equipment interaction; keep adapters blocked only where those decisions matter. Also copy the design's explicit full-health food test requirement into Task 5. `prototype/combat-engine.js:28–30` currently scales every card's power with attached dice and heals from pre-damage missing HP, so merely mapping metadata onto existing kinds silently chooses these behaviors.

3. **Medium — confirmed farm acquisition is missing from the complete plan.** The source card table requires Apple pickup from the farm. Task 5 covers satchel/battle use, Task 10 grants optional quest Apples, but no task switches the farm harvest into campaign inventory. `prototype/world-life.js:106` currently grants two Apples to legacy `state.food`, and GOODS at line 5 heals them for 7. Add an Act 1 farm harvest branch with saved availability, campaign quantity updates and tests; otherwise the new journey can harvest an incompatible legacy Apple or have no ordinary Apple source.

4. **Medium — preview NPC identity collision needs a concrete choice.** Task 2 says add Mara, while `prototype/world-life.js:58` already creates villager `id:'mara'`, “Mara the farmer,” and line 56 names Mara's cottage. The design also introduces Nell as farmer while promising existing residents remain available. Specify reuse of the existing Mara with preview-only topics or a distinct provisional neighbor identity; do not append another `mara` or overwrite legacy dialogue before opt-in. Test unique IDs and opt-in/reload/regeneration without duplicate villagers. Ivo and Tessa must be independently reachable through the nearest-entity selection at line 79.

5. **Medium — map knowledge requires a renderer seam in Task 2, not only saved ownership.** `prototype/game.js:84,87` uses `state.seen` for both landmark visibility and fog. Recording local map ownership cannot display the promised map knowledge unless rendering gains a separate knowledge predicate or a dedicated local-map view. State the selected route in Task 2, explicitly permit the small renderer seam if needed, and assert ownership reveals local knowledge without changing explored count or outside-region visibility. Task 6 currently names these tests, but Task 2 already promises this behavior.

6. **Medium — strengthen first-load and unsupported-save acceptance cases.** Task 1 asks for “unknown-version handling” without specifying preserve/reject behavior. `prototype/game.js:100` eagerly loads/generates; generation saves at line 28 before a late adapter runs. Require unknown/future campaign payloads to remain recoverable and never replace them with a fresh version during automatic hydration. Seed localStorage before loading scripts in a fresh VM, run the actual index order, and inspect storage after initialization and opt-in. Also exercise practice finish and leave paths (`prototype/map-combat.js:21–32`), which replace the whole `state` object, so the adapter cannot cache its previous `state.act1` reference. Existing smoke stubs return no speech action nodes; extend the Act 1 harness or verify real action wiring in a browser rather than invoking only internal event functions.

## Scope assessment

Tasks 1–3 can proceed while these targeted clarifications are incorporated. The pure model can test later event prerequisites without making combat or deferred puzzles playable. The proposed prologue preview is a clearly stated incremental implementation choice and must remain labelled as such; it is not the complete Act 1 journey. No issue found with the plan's explicit unresolved ending, separate Staff/Throw acquisition, null drop probabilities, local-only builds or preservation of unrelated working-tree changes.
